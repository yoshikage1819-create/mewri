# Mewri Delivery Checkpoints

Use these gates to resist building a large public service before the central
experience and trust boundaries work.

## Current: Local Demo To Closed Shared Beta

- Preserve the usable local demo.
- Complete authenticated server boundaries, storage upload, repository
  adapter, RLS, and rejected-access tests.
- Validate that invited people can contribute to and read one shared ZINE.

## Next: Repeatable Small Groups

- Measure theme view, post creation, ZINE completion, ZINE read, repeat
  participation, and invite acceptance.
- Improve the core loop before adding general social discovery.
- Add moderation, deletion, consent, privacy, and incident-response basics
  before expanding access.

## Later: Controlled Growth

- Expand only after retention and safety evidence exists.
- Require capacity, cost, abuse, privacy, backup, and rollback plans for public
  rollout.
- Treat 10,000 users as an outcome of validated retention and distribution,
  not as proof that unvalidated features should be built.

## Agent Boundary

AI may draft, code, test, analyze anonymous metrics, and propose experiments.
A human must approve live credentials, migrations, deployments, user-facing
communications, legal/privacy decisions, moderation decisions, and spending.

## Tool Routing

- Codex CLI is the primary executor and verifier for production-relevant code
  and shared-beta security boundaries.
- Cline is a useful editor-side planner and secondary implementer. Prefer its
  OpenAI Codex provider when eligible existing access is available.
- A Cline Provider model tagged `FREE` is suitable for exploration and narrow
  reversible work, but not as the sole implementation or review authority for
  shared-data security or deployment work.
- Consider Cursor Pro only if token or usage interruptions become a measured
  delivery blocker, or during sustained UI iteration where a one-month trial
  can be judged against time saved. It does not replace security review.
