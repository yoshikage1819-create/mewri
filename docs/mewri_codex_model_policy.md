# Mewri Codex Model Policy

作成日: 2026-05-22
状態: 作業前のモデル選択メモ

## 目的

Mewriの開発でCodex App/CLI/ChatGPTを使うとき、作業内容ごとに推奨モデルを選びやすくするためのメモです。

重要:

- Codex側から、ユーザーのアプリ設定モデルを直接変更することはできません。
- そのため、コードを書き換える前には「この作業の推奨モデル」を明示します。
- ユーザー側でモデルを切り替えたうえで、CLIやCodex Appに命令を渡す運用にします。

## 基本方針

### 5.3 Codex

通常の推奨モデル。

向いている作業:

- 既存コードを読んで小さく修正する。
- UIの文言やレイアウトを崩さず調整する。
- 設計書に沿って実装差分を入れる。
- typecheck/buildまで確認する。

Mewriでは、基本的にこのモデルで十分です。

### 5.5

重めの設計判断や、大きな機能分岐を扱うときに使います。

向いている作業:

- `自分の投稿` のデータ設計。
- hostテーマの権限設計。
- post-first / theme-first の設計整理。
- 共有DB、認証、グループ招待などの大きな設計。

### 5.4

UI実装や中規模の整理で、5.3より少し強く検討したいときに使います。

向いている作業:

- 複数ファイルにまたがるUI整理。
- スマホ/PC両対応のレイアウト修正。
- データ構造は大きく変えないが、コンポーネント分割を伴う修正。

### 5.4 mini

軽い確認や文章修正向け。

向いている作業:

- ドキュメントの言い換え。
- 小さい文言修正。
- CLI命令文の作成。
- 既存設計の要約。

コード変更には基本的に使わない方が安全です。

### 5.2

軽い確認用。

向いている作業:

- 文章の確認。
- 単純なチェックリスト作成。
- 小さい質問への回答。

Mewriの実装変更には基本的に使わない方が安全です。

## 作業別の推奨

| 作業 | 推奨モデル |
| --- | --- |
| v0.8の小さいUI修正 | 5.3 Codex |
| PC/スマホの表示崩れ修正 | 5.3 Codex または 5.4 |
| 設計書の日本語整理 | 5.4 mini または 5.3 Codex |
| `自分の投稿` の設計 | 5.5 |
| hostテーマの設計 | 5.5 |
| 共有DBや認証の導入 | 5.5 |
| build/typecheckの確認 | 5.3 Codex |

## 実装前の運用ルール

コードを書き換える前には、次を確認します。

```text
この作業はコード変更を含みます。
推奨モデル: 5.3 Codex
理由: 既存実装を壊さず、小さなUI/CSS修正を行うため。
```

大きな設計変更を含む場合:

```text
この作業は設計判断を含みます。
推奨モデル: 5.5
理由: データ構造、権限、将来拡張に影響するため。
```

## 現在の推奨

セルフチェック完了後の次作業は、近距離βの準備です。

推奨モデル:

- ドキュメント作成のみ: 5.4 mini または 5.3 Codex
- アプリの小さいUI修正が必要になった場合: 5.3 Codex
- v0.9の `自分の投稿` / hostテーマ設計に進む場合: 5.5
