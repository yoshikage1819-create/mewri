# Mewri Decision Log

作成日: 2026-05-20

復旧日: 2026-05-26

この文書は、文字化けしていた初期意思決定ログを、後続の MVP 文書と現行実装に整合する範囲で復旧したものである。意思決定の方向は変更しない。

## D001: Theme は毎日、ZINE は複数日の投稿から作る

### 決定

Mewri では Theme を毎日提示する。ZINE は毎日作らず、複数日分の投稿を束ねて生成する。

### 理由

Theme は軽い投稿の入口であり、日々提示することで参加しやすくなる。ZINE は投稿が作品としてまとまる報酬であり、毎日生成すると特別感と読み応えが弱くなる。

```text
Theme = 投稿習慣を作る入口
ZINE = 投稿を意味のある完成物にする報酬
```

### 採用する構造

```text
Theme
Post
ZineCycle
Zine
ZinePage
```

## D002: 初期検証では短い ZineCycle を優先する

### 決定

初期のクローズドテストでは短い Cycle を用い、投稿から ZINE 完成までの体験を早く確認する。

### 理由

初期に確認する価値は、完成度の高い長期作品よりも、写真が ZINE になる体験に参加者が価値を感じるかである。投稿量と継続利用が安定した後に、より長い Cycle を検討する。

## D003: 初期 MVP で複雑な共同編集や投票を必須にしない

### 決定

初期 MVP では、投稿を束ねた ZINE を生成して読むループを先に検証する。細かなページ編集、投票、高度な共同編集は後段に置く。

### 理由

まず検証すべきなのは、参加者の写真が一つの ZINE にまとまること自体の価値であり、編集機能の豊富さではない。

## D004: 一般公開 SNS より小さな Group を起点にする

### 決定

初期 Mewri は Follow や Discover を中心とした公開 SNS ではなく、小人数の Group での共同制作を中心にする。

### 理由

Mewri の核は不特定多数への拡散ではなく、数人が同じ ZINE に投稿し、完成物を共有する体験である。初期検証単位は小さな招待制 Group とする。

```text
Group
毎日の Theme
Group 内の Post
Cycle 完了後の ZINE
```

## D005: AI は補助であり主役にしない

### 決定

AI は Theme 候補、タイトル案、表紙案、ページ順、短いイントロなどの補助に使える。ただし ZINE の価値は参加者の投稿がまとまることに置く。

### 理由

AI が主役になると、投稿者の所有感と共同制作感が弱くなる。Mewri で主役となるのは人間の写真と参加である。

## D006: 方針がずれたときに戻る原則

```text
投稿は軽い
ZINE は深い
Theme は日々の投稿の入口
ZINE は複数日の投稿を束ねた完成物
AI は補助
意味は人間の参加から生まれる
Group から始め、公開 SNS 機能は後回しにする
```

新しい機能がこの原則に反する場合は、追加を保留して主ループの検証に戻る。
