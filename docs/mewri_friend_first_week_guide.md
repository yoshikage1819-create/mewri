# Mewri 友人検証: 最初の1週間ガイド

このガイドは、Mewri を技術的に評価するためのものではありません。
友人として実際に触って、どこで気持ちが動くか、どこで迷うかを見るためのものです。

## 目的

最初の1週間で知りたいことは、次の4つだけです。

1. Mewri が何をする場所か、友人が自分の言葉で説明できるか。
2. 今日のテーマを見て、写真を投稿する気持ちになるか。
3. 投稿が ZINE になる流れを見て、少しでも読み返したくなるか。
4. 次の日や次のテーマでも、もう一度開きたいと思うか。

「便利そう」や「いいと思う」だけでは判断しません。
実際に触った行動と、そこで出た正直な言葉を見ます。

## 友人にお願いすること

友人には、次のように伝えてください。

```text
Mewri の試作品を少し触ってほしいです。
技術の確認ではなく、使ってみたときの正直な感覚を知りたいです。

見てほしいのは、
- 何をする場所か伝わるか
- 写真を投稿したくなるか
- ZINE を読み返したくなるか
- 友達に見せたい感じがあるか
- 冷たい、わかりにくい、迷うところがあるか
です。

本物の個人情報やパスワードは入れないでください。
技術的な設定や Supabase / database / deploy などは触らなくて大丈夫です。
```

## 見る順番

1. 最初の画面を開く。
2. 何のサービスだと思ったかを言ってもらう。
3. 今日のテーマを見る。
4. 写真を1枚投稿してもらう。
5. ZINE を作る、または ZINE の読み返し部分を見る。
6. 最後に、もう一度使いたいかを聞く。

途中で迷ったら、その場で説明しすぎないでください。
「どこで止まったか」が重要な観察結果です。

## 聞く質問

検証後に、次をそのまま聞いてください。

```text
1. これは何をする場所だと思った？

2. 今日のテーマを見て、写真を投稿したくなった？
   その理由は？

3. 投稿から ZINE になる流れは、うれしい感じがあった？
   それともあまりピンとこなかった？

4. もう一度開くとしたら、どんな理由で開きそう？

5. 友達に見せたい、または誘いたいと思う瞬間はあった？

6. 冷たい、説明っぽい、SaaSっぽい、わかりにくいと感じたところは？

7. 逆に、Mewri らしくて残したいと思ったところは？

8. ひとことで言うと、今の Mewri はどんな場所？
```

## 観察メモ

オーナーは、友人の回答だけでなく、行動もメモします。

```text
検証日:
相手:
端末: PC / スマホ / タブレット

最初の説明なしで伝わったこと:

迷った場所:

自分から触った場所:

投稿まで進んだか:

ZINE まで見たか:

表情や言葉が強く動いた瞬間:

もう一度使いたいと言ったか:

友達に見せたいと言ったか:

次に直すなら1つだけ:
```

## 成功の目安

3人から5人に見せたあと、次が起きていれば前進です。

- 2人以上が「触ってみたい」と言う。
- 1人以上が、説明を聞きすぎずに投稿から ZINE まで進む。
- 1人以上が、Mewri を自分の言葉で説明できる。
- 1人以上が、ZINE を誰かに見せたい、またはもう一度見たいと言う。

逆に、全員が「きれいだけど何をするかわからない」「投稿する理由がない」と感じたら、
技術実装を進める前に体験設計を直します。

## local demo だけでは判断しにくいこと

友人から次のような反応が出た場合、それは重要な学びです。

```text
投稿が実際に共有されないと判断しにくい。
他の人と一緒に ZINE が完成していく感じがないと、Mewri の良さがわかりにくい。
```

この反応は、local demo の感想としては自然です。
Mewri の中心価値は、ひとりで画面を触ることではなく、少人数でテーマに投稿し、
一冊の ZINE に近づいていく感覚にあります。

そのため、local demo では次を見ます。

- 画面の意味が伝わるか。
- 投稿の導線で迷わないか。
- ZINE という読み返し方に可能性を感じるか。
- 共同体験があれば試してみたいと思うか。

一方で、次は local demo だけでは確定判断しません。

- 本当に友人同士で投稿が続くか。
- 他の人の投稿が見えたときに感情が動くか。
- ZINE が共同で完成していくことに価値を感じるか。
- 招待された小さなグループでまた戻りたくなるか。

この反応が出たら、次の判断は「UI をもっと磨く」だけではありません。
C-8e の安全確認を進め、最小の closed shared beta で共同体験を検証する必要があります。

## やらないこと

友人には、次を頼みません。

- コードを書くこと
- Supabase や database を触ること
- ログインや認証を判断すること
- セキュリティを評価すること
- 本番公開や deploy を判断すること
- 秘密情報、パスワード、API key、token、magic link を入力すること

危なそうな画面や言葉が出たら、そこで止めます。

## 次に進む判断

1週間の検証後、次のどちらかを選びます。

- 反応が弱い場合: UI、言葉、テーマ、ZINE の見せ方を直す。
- 反応が強い場合: C-8e の安全確認を進め、閉じた shared beta に近づける。

この順番を守ることで、Mewri は「安全に作る」だけでなく、
「本当に使われる理由があるか」を早く学べます。
