# Mewri URL Sharing Beta Readiness v0.9

更新日: 2026-05-22
対象: 単一ユーザー・ブラウザローカルURL共有デモ

## 目的
v0.8のMVPを壊さずに、URL共有で自己実施ベータを回せる状態にする。
この段階では「複数ユーザーで同期されるサービス」ではなく、「各参加者が自分のブラウザ内で試すデモ」として明確化する。

## 今回の変更
### 1. UI文言の監査と文字化け修正
- `apps/web/src/app/page.tsx` の表示テキストを全面監査し、文字化け（mojibake）を解消。
- 不自然な表現を、落ち着いた日本語のMVP向け文言に修正。

### 2. 単一ユーザー・ローカル保存の明示
- ホーム上部に `URL共有デモ` 注意ブロックを維持・強化。
- 以下を明記:
  - このURLは単一ユーザーのブラウザ内デモ
  - データは `localStorage` のみ
  - 他端末・他ユーザーには同期されない
  - ログイン/フォロー/通知/画像アップロードは未実装

### 3. プレースホルダーの未実装明示
- Section 3（フォロー中ユーザーの投稿）とSection 4（発見と回遊）の各カードに `未実装` / `将来検討` を明示。
- 実機能があるように誤解される文言を排除。

### 4. IAとMVP挙動の維持
- IA順序は維持:
  1. 参加中のZINE
  2. このZINEの中身
  3. フォロー中ユーザーの投稿（placeholder）
  4. 発見と回遊（placeholder）
- 投稿先は今日のアクティブテーマ固定。
- 未来テーマは投稿不可、クローズ済みテーマは閲覧のみ。
- 3日サイクル進捗 / ZINE生成 / 生成済みプレビューはSection 2で維持。

## 検証結果
- `npm.cmd run typecheck`: 成功
- `npm.cmd run build`: 成功
- `http://localhost:3000`: HTTP 200
- `http://192.168.1.11:3000`: HTTP 200（dev server稼働時）

## 明示的にスコープ外（未実装のまま）
- 共有DB / サーバー永続化
- 認証
- 実フォロー
- 通知
- host-created themes
- 自分の投稿
- post-first投稿
- 複数グループ投稿
- 実画像アップロード保存

## URL共有前の残リスク
1. 端末やブラウザが変わるとデータは引き継がれない（localStorage依存）。
2. ブラウザデータ削除で投稿・生成結果が消える。
3. 参加者が「共有サービス」と誤認する余地は、説明不足時にまだ残るため、配布時の案内文を必須にする。
4. 画像URL依存のため、外部URL切れで表示が不安定になる可能性がある（サンプル画像ボタン利用で回避可能）。
