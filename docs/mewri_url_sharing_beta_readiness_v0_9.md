# Mewri URL共有β Readiness v0.9

更新日: 2026-05-23
対象: 単一ユーザー・ブラウザローカルURL共有デモ
状態: Vercel公開URLで動作確認済み

## 目的

v0.9では、Mewriを「友人にURLで渡せる初期デモ」として確認する。

この段階の目的は、複数人が同じZINEに同期投稿することではない。目的は、各参加者が自分のブラウザ内でMewriの基本体験を試し、今日のテーマへの投稿、みんなの投稿、ZINE生成までの流れが伝わるかを確認すること。

## 公開形態

今回の公開形態:

- Vercel URLで共有する。
- データ保存は各ブラウザの `localStorage` のみ。
- 端末間、ブラウザ間、ユーザー間でデータは同期されない。
- ログイン、実フォロー、通知、画像アップロード、共有DBは未実装。

## 今回完了したこと

- GitHubリポジトリを作成し、初回コミットをpushした。
- Vercelにプロジェクトを接続した。
- monorepo構成に合わせて `vercel.json` を追加した。
- Vercel上のNext.js 16ビルド安定化のため、production buildをWebpackに固定した。
- Node.js engineを `22.x` に固定した。
- Vercelの公開URLでMewriが表示されることを確認した。
- 公開URL上でMVP導線が動くことを確認した。

## MVP導線の確認

確認済み:

1. ホームが表示される。
2. `参加中のZINE` が見える。
3. `今日のテーマ` が見える。
4. `今日の投稿をする` から投稿導線に入れる。
5. サンプル画像で投稿できる。
6. `みんなの投稿` から `このZINEの中身` に移動できる。
7. 投稿一覧に反映される。
8. 投稿数条件を満たすと `ZINEを生成` が使える。
9. 同じブラウザでは再読み込み後も状態が残る。
10. 別ブラウザ/シークレットでは状態が共有されない。

## 意図的に未実装のままにするもの

v0.9 URL共有βでは、次はまだ実装しない。

- 共有DB
- 認証
- 実フォロー
- 通知
- host-created themes
- `自分の投稿`
- post-first投稿
- 複数グループ投稿
- 実画像アップロード

## 残るリスク

1. `localStorage` 依存のため、ユーザー間で同じZINEは共有されない。
2. ブラウザデータ削除で投稿やZINE生成結果は消える。
3. 画像URL依存のため、外部URL切れで画像が表示されない可能性がある。
4. 受け手が「本番サービス」や「共有サービス」と誤解しないよう、配布文面でデモ制約を明示する必要がある。

## 友人に送る文面

```text
Mewriの初期デモです。
今日のテーマに写真を投稿して、みんなの投稿を見て、ZINEを生成するところまで試してみてください。

まだ本物のログイン、フォロー、画像アップロード、複数人での同期はありません。
投稿やZINE生成の結果は、あなたのブラウザ内だけに保存されます。

迷った場所、押したくならなかったボタン、意味が分からなかった言葉があれば教えてください。
```

## 次の判断

URL共有βで見るべきこと:

1. 初見の人が今日のテーマに投稿できるか。
2. `みんなの投稿` の意味が伝わるか。
3. `ZINEを生成` が報酬として見えるか。
4. localStorageデモであることが伝わるか。
5. 「今日のテーマ以外にも投稿したい」という声が出るか。
6. 「人間がテーマを作りたい」という声が出るか。
7. 「画像URLではなくアップロードしたい」という声が出るか。

## 次に進む候補

URL共有βの反応に応じて、次のどれかを選ぶ。

1. 共有感が足りない: 共有DB/招待設計へ進む。
2. テーマ外投稿が欲しい: `自分の投稿` を先に設計する。
3. 人間がテーマを作りたい: hostテーマを先に設計する。
4. 画像URLが分かりにくい: 画像アップロードを先に検討する。
5. まず見た目や文言で迷いが出た: v0.9のコピー/UI調整に戻る。
