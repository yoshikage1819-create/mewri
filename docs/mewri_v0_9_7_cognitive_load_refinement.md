# Mewri v0.9.7: Cognitive Load Refinement

## 目的

v0.9.6の画像投稿とZINE紙面表示を維持したまま、初見ユーザーが最初に見る情報を減らし、`今日の写真を投稿する` 行動に集中しやすくする。

## 受け取った評価から採用した判断

- 初回表示で進捗指標を複数並べると、投稿前の判断負荷が高い。
- 未実装のフォロー/発見を固定ナビゲーションに置くと、MVPの本導線に見えてしまう。
- ファイル選択は、標準の小さな入力より大きな投稿面として示した方が操作意図が伝わる。
- 完成ZINEは投稿カードのグリッドではなく、ページを順番に読む見せ方を優先する。
- モバイルではタップ面積と可読性を優先する。

## 変更内容

- 初回の参加中ZINEから予定テーマ表示を外し、今日のテーマと写真投稿に集中させた。
- 進捗カードは投稿が存在する場合のみ表示し、`あと何枚でZINEを作れるか` を主情報にした。
- 画像選択を大きなタップ可能エリアへ変更した。
- ZINE生成の数値表示を、複数の指標から一つのメッセージと進捗バーへ整理した。
- 下部固定ナビゲーションを実装済み導線の `参加中` と `中身` のみに絞った。
- 未実装のフォロー/発見セクションは、明示したまま折りたたみ内へ移動した。
- 完成ZINEページはデスクトップでも縦読みを基本とし、Feedのグリッドに見えにくくした。
- モバイルでZINEページが常に3列になり得るCSSルールを修正した。

## 採用しなかった提案

- 投稿一覧を投稿フォームと同じカードにまとめることは採用しない。投稿行動と、蓄積された内容を読む行動は区別した方がMewriの制作体験に合う。
- 進行中カードへの強いアニメーションは追加しない。β段階では動機を演出で増幅する前に、意味が伝わるかを確認する。
- `ZINE` という名称は消さない。初見の分かりやすさは補助文言と画面構造で支え、ブランド語は保持する。

## 次に確認すること

1. 初見で最初に写真選択へ進めるか。
2. 投稿後の `あと何枚` 表示が、ZINEを作る理由として理解されるか。
3. 生成済みZINEを投稿一覧ではなく、読む対象だと感じるか。
4. 折りたたんだ未実装機能が、本導線の邪魔にならないか。
5. スマホとPCの両方で、写真選択とZINE閲覧が崩れないか。
