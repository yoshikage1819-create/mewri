# ローカルデモ確認ガイド（非技術者向け）

更新日: 2026-06-02

## この文書の目的

Mewri の**ローカルデモ**を、開発に詳しくない方が安全に開いて、触って、感想を伝えるための手順書です。  
コードやサーバー設定は触りません。

## ローカルデモとは

- あなたの PC（または同じ Wi‑Fi 上のスマホ）のブラウザだけで動く**試作品**です。
- 「今日のテーマ → 写真を投稿 → ZINE に貢献 → 生成 ZINE を読む」という流れを体験できます。
- 写真と投稿は**そのブラウザにだけ**残ります（この端末の中だけの練習用データ）。

## ローカルデモではないもの

次は**この画面では動いていません**。混同しないでください。

| 項目 | ローカルデモでの状態 |
| --- | --- |
| 本番の Mewri サービス | 別物です |
| 本番のユーザーデータ | 使いません |
| 非公開ベータの参加者データ | 使いません・入力しないでください |
| ログイン・アカウント | ありません |
| 他の人との共有・同期 | ありません |
| クラウドへの写真保存 | このデモでは行いません |
| 本番公開・ステージングの有効化 | 行いません |

## 開き方（開発担当者に頼む前の確認）

通常は、開発担当者が次を済ませたあと、あなたに URL を渡します。

1. 作業フォルダ `C:\dev\mewri\ph-cursor` を Cursor で開く（OneDrive 内の古いフォルダは使わない）。
2. ターミナルで `npm.cmd install`（初回のみ）のあと `npm.cmd run dev` を実行する。
3. ブラウザで `http://localhost:3000` を開く。

スマホ実機で見る手順は別文書です（開発担当者向け）:  
[`mewri_mobile_preview_v0_5.md`](../mewri_mobile_preview_v0_5.md)

## 画面の見方（上から）

| 場所 | 内容 |
| --- | --- |
| ヘッダー | グループ名・日付・「リセット」など |
| 黄色い帯 | **デモ（この端末だけ）** — データはこのブラウザだけに保存される旨 |
| 折りたたみ「この画面の範囲と注意」 | **安全案内**（下記） |
| **1. 参加中のZINE** | 今日のテーマ・写真投稿（主な操作） |
| **2. このZINEの中身** | 投稿一覧・ZINE 生成・読む |
| **感想・改善のメモ** | **フィードバック用メモ**（下記） |
| 「今後追加予定の機能」 | 未実装のプレースホルダー（本番機能ではない） |

## 安全に試していいこと

- サンプル画像やサンプル投稿を使って、投稿の流れを試す。
- 写真を選んで投稿し、進捗表示や ZINE 生成を試す（データはこの端末だけ）。
- 画面を読み、わかりにくい文言やボタンの位置をメモする。
- 下の「感想・改善のメモ」に書く（送信ボタンはありません）。

## 入力・操作してはいけないこと

次は**絶対に入力・貼り付けしない**でください。

- パスワード、API キー、トークン、魔法のリンク URL などの**秘密情報**
- 本番やステージングの**ログイン情報**
- **実在する参加者**の本名・メール・電話・住所・顔写真など、私的な個人情報
- 本番データベースや Storage のパス・接続文字列
- 「とりあえず本番 URL を開いて試す」など、**本番・ステージングの有効化**

画像 URL の上級入力欄（「URL入力（上級）」）も、秘密の URL や本番用アドレスを入れないでください。

## 安全案内の場所

画面上部、黄色い「デモ（この端末だけ）」のすぐ下にある  
**「この画面の範囲と注意（開発・確認用）」** を開くと、次が書いてあります。

- ローカルデモであること
- 本番データを使わないこと
- ログイン・クラウド DB・クラウド保存・サーバー側の安全設計は、この画面作業の対象外であること
- 本番に近い形で出す前に Codex による確認が必要なこと

## フィードバック用メモの場所

**「2. このZINEの中身」** のあと、「今後追加予定の機能」の**前**にあります。

含まれるもの:

- 「この端末の画面にだけ表示される。送信・保存されない。再読み込みで消える」という説明
- 感想・改善点を書く入力欄
- 文字数表示（例: `12文字 / 最大500文字`）
- **「メモを消す」** ボタン（入力を空にするだけ）

**「送信」ボタンはありません。** サーバーには送られません。

## 感想の伝え方（手動）

1. メモ欄に書く（または別のメモ帳に写す）。
2. 開発担当者に、次のいずれかで渡す（**秘密情報は含めない**）:
   - チャットに文章を貼る
   - メール・ドキュメントに箇条書きで書く
   - 画面のスクリーンショット（個人情報が写らないよう注意）
3. 可能なら **日付・端末（PC / スマホ）・画面幅** を一言添えると助かります。

例:

```text
【ローカルデモ感想 2026-06-02】
- PC Chrome、幅 390px 相当
- 「ZINEを作る」まで進めた。ボタンはわかりやすかった。
- テーマ切り替えの pills が横に長く、指で押しづらかった。
```

## Codex の確認を待つべきこと

次は、ローカルデモの見た目だけでは決められません。**Codex（開発用 AI）の確認後**に進みます。

- 本番や共有ベータへの接続
- ログイン・認証の実装
- データベース・写真のクラウド保存・サーバー側の安全な受け渡し
- マイグレーションの適用
- デプロイ・ステージングの有効化
- `main` ブランチへのマージ判断

あなたの役割は、**ローカルデモの使いやすさと文言**のフィードバックです。  
サーバー設定やセキュリティの最終判断は開発担当者と Codex に任せてください。

## 困ったとき

| 状況 | 対応 |
| --- | --- |
| 画面が真っ白 | 開発担当者に「`npm.cmd run dev` が動いているか」を確認してもらう |
| データを最初からやり直したい | ヘッダーの「リセット」（確認ダイアログが出ます） |
| 本番と思って不安 | この文書の「ローカルデモではないもの」を再確認 |
| 秘密らしきものを入れてしまった | すぐ開発担当者に連絡。メモ欄は「メモを消す」。本番 URL や鍵は再入力しない |
